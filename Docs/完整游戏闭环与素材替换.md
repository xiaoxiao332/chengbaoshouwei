# v0.4 完整闭环与交付验收

本文件把产品规则转换成可操作的端到端验收。实现状态见 `开发进度.md`。

## 完整流程

1. Boot 加载设置、存档、Schema v14 配置和本地 Addressables。
2. Selection 显示金币、卡牌、地图和三个模式。
3. 玩家提交 BattlefieldId、MapModeId、MatchId，加载 Gameplay。
4. MatchSetup 冻结配置快照并创建双方系统。
5. 双方采集、加工、建造、研究、训练、部署和战斗。
6. Tick 600 打开玩家四选一并暂停；敌方同类奖励不暂停玩家。
7. Boss、箭塔、资源刷新和阶段效果按配置运行。
8. 城墙归零后锁定结果，ResultPanel 暂停并展示明细。
9. MatchId 防重结算并原子保存，返回 Selection。

## 资源闭环

`资源点 → 采集者到达 → 扣除节点余量 → 携带返回 → 城门入库 → 加工/消费`

- 3+6+3 节点、六波激活、45/180 秒刷新符合配置。
- 节点刷新后旧 SpawnRevision 目标失效。
- 采集者死亡不入库；满仓、无目标和费用不足不会制造资源。
- 敌我所有收支可从账本复核。

## 建筑与训练闭环

`建筑卡 → 蓝图 → 合法槽位事务 → 建筑完成 → 营地激活士兵卡 → 训练订单 → 部署 → Unit AI`

- 非法位置、取消、资源不足和队列满不消耗卡牌/费用。
- 建筑位、手牌、库存和队列上限始终有效。
- 研究只影响完成后新训练/部署单位。

## 四选一闭环

- Tick 600 自动打开，四项顺序为建筑/建筑/资源/援军。
- 两张建筑不同且优先补缺。
- 资源奖励直接入库。
- 援军领取进入道具手牌；非法落点/取消不消耗，合法部署成功后消耗。
- 满手时建筑/援军进入替换或放弃，资源仍可领取。
- 领取后恢复模拟，并按热度设置下一次冷却。
- Choice0–2 无组合视图，Choice3 唯一保留；中文名称和稀有度可读。

## 战斗、Boss 与箭塔

- 单位目标、弹体、伤害、爆炸和城墙结算只发生一次。
- 已部署单位自动推进；战略 AI 不直接移动单位。
- Boss 受击反击、技能预警、死亡掉落和自然接触领取可见且可复核。
- 箭塔必须经过卡牌、费用、位置、施工和上限校验。

## 结算与存档

- Combat 只锁定一次 MatchResult。
- Settlement 使用 MatchId 防重复发放金币。
- SaveCoordinator 原子写入；失败不得产生半完成状态。
- 返回 Selection 后无 Gameplay 系统、资源租约、弹体或暂停原因残留。
- 第二局可重新进入 Gameplay。

## 素材替换

1. 准备透明 PNG 或地图背景。
2. 通过 Unity MCP/Editor API 设置 Importer。
3. 注册稳定 PresentationKey、ResourceKey 和 Addressables 组。
4. 更新 Catalog/Prefab 引用，不修改业务 ID。
5. 回读类型、GUID、地址、Prefab 引用和显示结果。
6. 运行内容校验、相关测试和双分辨率截图。

禁止用同名新文件绕过 GUID 检查，禁止把玩法数值写进 PresentationCatalog，禁止手改 Prefab/ScriptableObject YAML。

## 自动化开发验证

1. 保持 Android Build Target，完成平台切换后的编译与 Console 检查。
2. Schema v14 定向 EditMode。
3. 完整非 Explicit EditMode。
4. 完整 PlayMode。
5. 两地图×三模式 9000 Tick 回归。
6. 36×50 Explicit 平衡子批（玩法/平衡变更时才重跑）。
7. Config/ProjectContent/Prefab/Importer/Addressables 校验。
8. 固定 1920×1080 最终截图。
9. Android 目标的 Addressables Local Content Build。

以上 1–9 项构成 Codex 的 Android 目标 Editor/Addressables 开发验证。截图必须校验真实 PNG 像素尺寸，不能只依赖文件名或 `Screen.SetResolution` 调用。

## 项目负责人真机验收

以下内容不属于 Editor/Addressables 自动化通过范围，由项目负责人在设置正式包名和签名后执行：

1. 生成 ARM64 IL2CPP Android APK/AAB。
2. 安装并验证 Boot→Selection→Gameplay→ResultPanel→Selection。
3. 验证 Android 固定 1920×1080 布局、Safe Area、触控、切后台和生命周期。
4. 验证性能、温度、内存、长局稳定性和真人体验。

任何未实际执行项都在 `开发进度.md` 标记“未验证”，不能继承旧结果。
