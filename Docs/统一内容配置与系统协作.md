# 统一内容配置与系统协作

## 根入口与版本

- 根资产：`Assets/Game/Content/Config/GameContentConfig.asset`。
- 当前 SchemaVersion：14，必须精确匹配 `ContentConstants.ExpectedSchemaVersion`。
- 根资产只聚合 Catalog，不保存运行状态，也不是 Service Locator。
- 创建对局时解析并冻结 MatchConfigSnapshot；运行中不热切换配置资产。

## Catalog 所有权

| Catalog | 唯一拥有内容 | 主要消费者 |
|---|---|---|
| ResourceCatalog | 九种局内资源、分组、容量语义、显示精度 | Economy、HUD |
| CardCatalog | 卡牌类型、关联内容、解锁/成长、表现键 | Selection、Hand、Camp |
| BuildingCatalog | 建筑生产、采集营、营地、仓库、研究和升级 | Building、Economy、Research |
| UnitCatalog | 单位基础属性、角色、训练时间、弹体 | Training、Combat |
| BattlefieldCatalog | 地图、墙体、12 节点、路线、部署区、Boss、模式入口 | MatchSetup、Resource、Combat |
| RewardCatalog | 稀有度、资源包、援军模板、奖励表现键 | Reward、AI |
| StageEffectCatalog | 模式、阶段、热度、AI 权重和敌方经济 | MatchPhase、AI |
| ProgressionConfig | 金币、解锁、升级公式和地图门槛 | Selection、Save |
| SceneKeyCatalog | 稳定 SceneKey | SceneFlow |
| PresentationCatalog | Panel/Sprite/Prefab/Audio 的 ResourceKey | Presentation |

跨 Catalog 只保存稳定强类型 ID。Definition 不互持可变 ScriptableObject 图，运行时消费者只接收所需窄接口。

## 稳定 ID

- `ResourceId`、`CardId`、`BuildingId`、`UnitId`、`BattlefieldId`、`MapModeId`、`RewardId`、`PresentationKey` 发布后不得复用或静默改名。
- 显示名、稀有度、图标和数值可以升级，但不能改变稳定 ID 语义。
- 必须改 ID 时先提供存档映射和内容校验。

## Schema v14 Battlefield 配置

每张地图必须：

- 恰好 3 个玩家安全点、6 个中场候选点、3 个敌方安全点。
- 安全点按路线一一镜像并满足等墙距公式。
- 六个中场坐标唯一。
- 配置初始容量、刷新容量和刷新延迟。
- 恰好包含 60/60/120/180/240/300 秒六波激活。

安全路线资源映射由 MatchSeed 无重复洗牌；中场后两波和刷新使用 25/25/30/20 权重。

## Schema v14 Reward 配置

- OfferCandidateCount 固定为 4。
- 五层稀有度权重：100/0/0、75/25/0、60/40/0、50/40/10、45/40/15。
- 建筑候选至少存在两个合法且不同的 CardId。
- `card.battlefield.arrow-tower` 必须进入双方共享的建筑奖励池，并以确定性随机概率出现；其卡牌类型仍为 BattlefieldItem。
- 资源包按三种组合×三档稀有度显式配置，共九个 BundleId。
- Common 资源量使用基数，Rare/Epic 使用 6→8/9、12→15/18。
- 援军模板沿用稳定 TemplateId/CardId；最低热度 0/1–2/3 对应 Common/Rare/Epic。
- 三个表现键：
  - `presentation.reward.building → art.reward.building`
  - `presentation.reward.resource → art.reward.resource`
  - `presentation.reward.reinforcement → art.reward.reinforcement`

## 配置到运行时

`Infrastructure 加载根配置 → ContentConfigSystem 全量校验 → 冻结窄 Match 快照 → Bootstrap 显式注入系统`

- 小数权重在初始化时量化为整数。
- 快照复制列表，不暴露可变 Definition。
- UI 从 Gameplay ViewModel 获得玩家文案和表现键。
- AI 和玩家使用相同 Reward/Building/Training 等业务接口。

## 事务

- 建造：校验卡牌、手牌、槽位、费用和位置后一次提交；失败不消耗。
- 建筑运行：加工输入或付费采集派遣消费失败时锁定暂停；补充库存不自动恢复，继续命令只解锁运行，下一次消费仍原子校验。
- 资源奖励：校验容量后直接入库，不占手牌。
- 援军：领取进入手牌；选择/取消/非法落点不消耗；合法部署订单提交成功后消耗。
- 满手替换：新奖励和旧牌交换必须是单一原子事务；取消保持两者不变。
- 结算：Combat 锁定结果，Settlement 按 MatchId 防重，SaveCoordinator 原子保存。

## 内容校验

必须拒绝：

- Schema 不匹配、空/重复 ID、缺失引用、类型不匹配。
- 非 3+6+3、坐标重复、墙距不等、波次数量/时序错误。
- 稀有度权重非法、缺少资源档位、援军热度/稀有度冲突。
- 四槽不足、奖励表现键缺失、Sprite 类型错误或 Addressables 未注册。
- 未解锁/不可达内容进入初始手牌或建筑奖励候选。
- ResourceCatalog 与 PresentationCatalog 同地址不同类型。

配置、Prefab 或 Addressables 变化后运行 `ContentConfigValidator` 与 `ProjectContentValidator.CollectIssues()`，结果必须为 0。
